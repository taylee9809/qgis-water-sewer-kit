# 00 온보딩 — 프로젝트에 킷 맞추기

킷의 스킬(11·12·30·32·40·51)은 실제 레이어 이름을 모른다. **논리 이름**만 알고, 실제 이름은
프로젝트 루트의 `sewer.config.json` 에서 읽는다. 이 스킬은 그 파일을 만든다.

- 킷 루트: 이 SKILL.md 의 두 단계 위 폴더(`skills\00-onboard\..\..`). 아래 경로는 킷 루트 기준.
- 논리 이름 정의: `standard\data-standard.md` — **먼저 읽는다.**
- 설정 틀: `templates\sewer.config.example.json` (우리 팀 실제 구성이 예시로 들어 있다)
- 업무 흐름: `standard\workflow.md`

## ★ 원칙
- **원본 데이터는 읽기만 한다.** 조사·검사 스크립트는 읽기 전용이다. 이 단계에서 레이어를 고치거나 이름을 바꾸지 않는다 — 대응은 설정으로 한다.
- **비밀번호는 묻지도 적지도 않는다.** PostGIS 를 쓰면 사용자에게 환경변수(`SEWER_PG_PASSWORD` 등)를 직접 설정해 달라고 안내하고, 대화에 값을 붙여 넣지 말라고 말한다.
- 사람에게는 **확신이 없는 것만** 묻는다. 이름·표본값·범위로 확정되는 것은 묻지 않는다.

## 1. 위치 파악 (사람에게 물을 것은 이것뿐)
1. 프로젝트 루트 폴더 — 보통 지금 작업 폴더. `sewer.config.json` 이 여기 생긴다.
2. 데이터 위치 — GPKG 폴더, PostGIS(host:port/dbname, 사용자명), QGIS 프로젝트(.qgz).
   `.qgz` 가 있으면 그게 가장 좋은 지도다(레이어 그룹 이름이 용도를 알려 준다).

## 2. 조사 — `scripts\probe.py`
```
python -X utf8 "<킷>\skills\00-onboard\scripts\probe.py" <GPKG폴더 또는 파일…> <프로젝트.qgz> ^
       [--postgis localhost:5432/DBNAME --user postgres --password-env SEWER_PG_PASSWORD] --out _산출\00-onboard
```
산출 `_산출\00-onboard\inventory.md` — 레이어마다 기하·건수·좌표계, 필드마다 채움률·표본 3개·숫자 범위.
QGIS 프로젝트는 그룹/레이어/공급자 표. 대형 DB 는 1분 남짓 걸린다.

## 3. 대응표 만들기 (Claude 가 판단)
`inventory.md` 를 `standard\data-standard.md` 의 논리 레이어·필드와 짝짓는다. 근거는 셋을 함께 본다.

| 근거 | 예 |
|---|---|
| 이름 | `관번호`/`PIPE_ID`/`관로번호` → `pipe_id`, `상류관저`/`IL_UP`/`시점관저고` → `us_invert` |
| 표본값 | `자연유하`·`압송`·`가압` 이 나오면 `kind` · `기존폐쇄`·`폐쇄` 면 `status` |
| 범위 | 관경 75~1000 · 관저고 범위가 지반고보다 1~5 m 낮음 · 연장 0.5~400 |
| 기하·그룹 | 계획관로 = Line + 「실시설계」류 그룹 · 맨홀 = Point(또는 작은 Polygon) · 준공 = 「준공」 그룹 |

각 짝에 **확실 / 추정 / 없음** 을 붙여 표로 정리한다(`_산출\00-onboard\mapping.md`).
- 상류·하류가 접두어 대신 `시점/종점`, `1/2` 로 된 경우 — 숫자 범위로 어느 쪽이 높은지 보고 확정한다(자연유하는 상류가 높다).
- 같은 역할의 레이어가 둘 이상이면(회차별 사본 등) **최신 자료기준일·가장 많이 채워진 것**을 고르고 나머지는 대응표에 「후보」로 남긴다.
- 우리 표준에 없는데 그 팀에 있는 레이어는 무시하지 말고 대응표 끝에 「표준 밖」으로 적는다(나중에 스킬로 올릴 후보).

## 4. 사람에게 묻기 — 한 번에 모아서
`추정`·`없음` 인 것과 아래 규약만 묻는다. 질문은 5개 안팎으로.
- 관번호 규약 — 관번호 = 상류 맨홀 번호인가?
- 압송·자연유하·기존폐쇄를 그 팀은 무슨 말로 쓰는가(표본값으로 못 정했을 때만)
- 준공(기존) 관로 DB 가 있는가 — 없으면 12 스킬부터 해야 40 검토가 선다
- 설계기준 — KDS 기본값(최소토피 1.0 m · 최소경사 5‰ · n 0.011 · 최소관경 200)을 쓰는가, 과업 기준이 따로 있는가
- 외주 설계사 납품 폴더가 쌓이는 곳과 폴더 이름 규칙(40 스킬용, 해당 시)

## 5. 설정 쓰기
`templates\sewer.config.example.json` 을 프로젝트 루트에 `sewer.config.json` 으로 복사해 고친다.
- 대응표의 확실·확인된 값만 넣는다. **없는 레이어·필드는 키째 지운다**(빈 문자열로 두지 않는다).
- 경로는 프로젝트 루트 기준 상대경로. `outputs.root` 는 원본 폴더와 겹치지 않게.
- `_` 로 시작하는 설명 키는 남겨 두되, 예시 값(우리 팀 구성)은 그 팀 것으로 바꾼다.

## 6. 검사 — `scripts\check_config.py`
```
python -X utf8 "<킷>\skills\00-onboard\scripts\check_config.py" --config sewer.config.json
```
- 치명 0 이 될 때까지 5↔6 을 반복한다.
- ⚠ 는 데이터 품질 정보다(채움률 낮음, 코드값 뒤섞임, 관번호 중복, 도형 방향 의심). 설정으로 못 고치는 것은 **사람에게 보고만** 하고 데이터를 고치지 않는다.
- 도형 방향 의심(갈라지는 노드·마주보는 끝이 여럿, 역경사 다수)이 나오면 `standard\pitfalls-qgis-postgis.md` 「관로 도형 방향」을 근거로 따로 알린다.

## 7. 프로젝트에 자리 잡기
1. `templates\CLAUDE.md` 를 프로젝트 루트에 `CLAUDE.md` 로 복사하고 「이 프로젝트」 절(용역명·범위·지구·특이 규약·결정)을 채운다. 이미 CLAUDE.md 가 있으면 덮지 말고 그 절만 덧붙인다.
2. 프로젝트 루트에 `scripts\`(이 프로젝트 전용 스크립트) · `결정기록.md`(기준값을 바꾼 결정과 근거)를 만든다.
3. 사람에게 보고: 대응표 요약 · **못 쓰는 스킬과 이유**(예: 준공 레이어 없음 → 40 의 A4 생략) · 데이터 품질 ⚠ 목록 · 다음 할 일 1~2개.

## 끝났는지 확인
- [ ] `sewer.config.json` 이 프로젝트 루트에 있고 `check_config.py` 치명 0
- [ ] 대응표(`mapping.md`)에 추정 항목이 사람 확인으로 모두 확정
- [ ] 비밀번호가 설정 파일·대화·로그 어디에도 없다
- [ ] 프로젝트 `CLAUDE.md` 의 「이 프로젝트」 절이 채워졌다

## 다음 회차·다른 용역
레이어가 추가·개명되면 2(probe)를 다시 돌려 `inventory.md` 차이를 보고 설정만 고친다.
새 용역이면 그 프로젝트 폴더에서 이 스킬을 처음부터 다시 한다(설정은 프로젝트마다 하나).
