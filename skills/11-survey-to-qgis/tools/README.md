# 측량현황도 → QGIS 지장물 변환·검사 도구

측량현황도 DXF에서 지장물(횡배수관·측구·BOX·암거)을 QGIS 폴리곤 레이어로 만들고,
**추측으로 만든 부분을 찾아내 걸러내는** 도구 묶음이다. 실무 회차에서 오류 19건을 잡아낸
절차를 그대로 스크립트로 만든 것을 킷용으로 일반화했다 — 경로·레이어·필드는 프로젝트의
`sewer.config.json` 하나로 맞춘다(판정 로직·임계값은 원본 그대로).

---

## 왜 오류가 생기나 (이걸 알아야 도구를 믿고 쓸 수 있다)

측량현황도는 **그림**이다. 지장물이 "폴리곤 + 속성"으로 들어 있지 않고,
선 몇 개와 떨어진 텍스트 하나로 표현돼 있다. 그래서 변환은 변환이 아니라 **추측 3단계**가 된다.

| 추측해야 하는 것 | 도면이 주는 것 | 생기는 오류 |
|---|---|---|
| ① 어떤 선들이 한 지장물인가 | 선 몇 개 (끝점이 1.6~5.5 mm 어긋남) | 폐합 실패, 조각난 폴리곤 |
| ② 그 지장물의 폭이 얼마인가 | 평행 2선이면 간격, ㄷ자·단선이면 없음 | **두께 2배 ㄷ자**, 기본폭 0.3 추정 |
| ③ 어느 텍스트가 어느 지장물 라벨인가 | 관로 1개당 라벨 1개, 떨어져 있음 | **라벨 오귀속** |

여기에 도면 쪽 사정이 겹친다.

1. **작도 방식이 한 도면 안에 4가지 섞여 있다** — 평행 2선(관벽) / ㄷ자(두 변 + 막힌 끝 한 변) /
   단선 하나 / 닫힌 폴리라인. ㄷ자를 한 줄로 오인하면 외곽선 전체가 두꺼워진다.
2. **라벨 1개 : 폴리곤 N개** — 인접 승계로 전파하는데, 그 과정에서 몇 m 떨어진 다른 지장물이
   라벨을 받아간다.
3. **규격 표기 규약이 뒤섞여 있다** — `D600` / `%%C600` / `U0.6X0.6` /
   `U형측구06x06`(2자리 `0N` 은 0.N m) / `Box 2@3.0X2.0` / 접두어 없는 `4.5X1.0` / `H1.5`.
4. **납품이 누적본** — 새 회차 도면이 지난 회차를 포함한다. 겹침비 0.3 기준으로 중복 제거가 필요하다.

그리고 **반복된 진짜 이유**: 지난 회차에 손으로 고친 보정(ㄷ자 120건, 보로노이 중심선 65건,
미상→실측폭)을 빌더 코드에 넣지 않아 다음 회차에 그대로 재발했다.
→ **03·04·05가 그 손보정을 "규칙"으로 만든 것이다.** 빌드할 때마다 돌려야 한다.

## 설정 (`sewer.config.json`)

모든 스크립트는 `--config <경로>` 를 받는다. 생략하면 환경변수 `SEWER_CONFIG`, 그다음 현재 폴더에서
위로 올라가며 `sewer.config.json` 을 찾는다. **명령줄 인자(`--gpkg` `--poly` `--cl` `--route` `--src`
`--jijeok` …)를 주면 그게 설정보다 우선**한다. 산출물(CSV·확인용 GPKG·그림)은
`<outputs.root>/11-survey/` 아래에만 쓴다(`--outdir` 로 바꿀 수 있다).

| 키 | 쓰는 곳 | 비고 |
|---|---|---|
| `layers.obstacle_poly` / `obstacle_line` | 03~15 | 지장물 정본 폴리곤·중심선. **GPKG 만**(직접 고치므로). 같은 GPKG 여야 한다 |
| `layers.obstacle_review` / `obstacle_review_line` | 03·05·06 `--review`, 11 | 확인필요 폴리곤·중심선. 없으면 `<산출>/지장물_확인필요.gpkg` · `확인필요_폴리곤`·`확인필요_중심선` |
| `layers.plan_pipe` + `fields.plan_pipe.pipe_id` / `district` | 06·07·08·11·12 | 설계 노선(관번호 = .flo 상류관번호). PostGIS 도 된다 |
| `layers.parcel` + `fields.parcel.jibun` | 13 | 지적. 지번 필드 끝 글자가 지목(연속지적도 `JIBUN` 형식 `123-4 구`). GPKG·SHP·PostGIS |
| `fields.obstacle_poly.fix_note` | 03·04·05·09·11·12·14 | 보정 기록 필드. 없으면 쓸 때 `보정_<오늘 YYMMDD>`, 읽을 때 `보정_YYMMDD` 전부 |
| `survey.dxf_dir` | 01 | 측량 DXF 가 들어오는 폴더(인자 없이 01 을 부르면 목록을 보여 준다) |
| `survey.design_check_gpkg` | 06·07·08·11·12 | 노선을 이 GPKG 에서 읽는다(레이어명 = `layers.plan_pipe.layer`). `plan_pipe` 가 PostGIS 일 때 GPKG 사본을 쓰고 싶으면 |
| `survey.build_gpkg` | 02 `--out` · 05·07·11 `--srcgpkg` | 02 빌드 GPKG(`지장물_폴리곤_<접미>` 레이어가 쌓이는 곳) |
| `survey.current_districts` | 07·08·11·12 | '금회 노선' 지구 목록(값은 `fields.plan_pipe.district` 의 값과 **정확히 일치**). 비우면 전체 노선이 금회 |
| `survey.flo` | 06 | 설계사 종단 `.flo` 경로 목록 |
| `survey.parcel_encoding` | 13 | 지적 SHP 인코딩(기본 `cp949`) |
| `project.crs` | 전부 | 출력 좌표계(기본 EPSG:5186) |

```json
"layers": {
  "obstacle_poly":        {"src": "data/지장물_정본.gpkg", "layer": "지장물_폴리곤_정본"},
  "obstacle_line":        {"src": "data/지장물_정본.gpkg", "layer": "지장물_중심선_정본"},
  "obstacle_review":      {"src": "data/지장물_확인필요.gpkg", "layer": "확인필요_폴리곤"},
  "obstacle_review_line": {"src": "data/지장물_확인필요.gpkg", "layer": "확인필요_중심선"}
},
"survey": {
  "dxf_dir": "00 측량조사",
  "design_check_gpkg": "data/실시설계_통합.gpkg",
```

## 출력 스키마 (킷 표준 — 바꾸지 않는다)

이 도구가 **새로 만드는** 지장물 레이어의 필드 이름은 킷 표준이다. 03~15 는 정본 레이어를 이 이름으로
읽는다. 그래서 `fields.obstacle_poly` 의 `obs_id` `class` `type` `label` `width_m` `height_m` `dia_mm`
매핑은 아래 이름과 같아야 한다(다르면 실행할 때 경고만 찍는다). 설정으로 바꿀 수 있는 것은
보정 기록 필드(`fix_note`)뿐이다.

| 레이어 (02 `--suf` 접미) | 필드 |
|---|---|
| `지장물_폴리곤_<suf>` · `지장물_중심선_<suf>` | `지장물번호`(J0001…) `분류` `종류` `표기` `규격_폭m` `규격_깊이m` `연수` `관경mm` `관경산출`(생성 근거) `실측폭m` `실측장변m` `면적m2` `구분`(현행/매립) `생성방식`(폐합(도면)·자동폐합(체인쌍)·단선버퍼) `출처` (+ `--prev` 레이어에 있던 `IN_EL` `OUT_EL`) |
| `지장물_확인필요_폴리곤_<suf>` · `…_중심선_<suf>` | 위와 같음 — 단선버퍼·추정(기본폭)만 |
| `하수기존_시설_<suf>` | 위 + `X` `Y` (`지장물번호` S0001…, 오수맨홀·정화조 심볼) |
| `지장물_맨홀_<suf>` | `맨홀번호` `분류` `관종형` `관경mm` `관경_원문` `규격_폭m` `규격_깊이m` `IN_EL` `OUT_EL` `IN_원문` `OUT_원문` `기타표기` `위치출처` `맨홀규격m` `X` `Y` `출처` |
| `지장물_미폐합_잔여선_<suf>` | `구분` `연장m` |
| 확인필요(11 이 만든다) | `지장물번호` `종류` `표기` `규격_폭m` `규격_깊이m` `관경mm` `구분` `실측폭m` `면적m2` `생성방식` `분리사유` `분리일시` `금회노선거리m` `금회관번호` |

정본(여러 빌드를 합친 레이어)은 번호에 빌드 접미를 붙인다: `v3-J0001`. 정본에 `관경산출` 이 없으면
05·07·11 이 `survey.build_gpkg` 의 `지장물_폴리곤_<접미>` 레이어에서 `<접미>-J0001` 로 생성 근거를 찾는다.
보정 기록은 `보정_YYMMDD` 필드(또는 `fix_note`)에 문장으로 남는다.

## 근거의 세기로 레이어를 가른다

| 생성 경로 | 근거 | 가는 곳 |
|---|---|---|
| 폐합(도면) | 도면이 관의 양쪽 벽을 직접 닫아놨다 | 지장물 |
| 체인쌍(평행 2선) | 두 선 간격이 곧 관경 | 지장물 |
| **단선버퍼 · 추정(기본폭)** | "그 선이 배수시설물 레이어에 있다"뿐 | **확인필요** |

측량도는 **경계선·구조물선도 `배수시설물` 레이어에 그려 넣는다.** 레이어만 확인해도 안 걸러진다
(사례: 교량 옆 강·도로 경계선 2.29 m 가 옆 암거의 `2@2.0x1.5` 라벨을 상속받아 9.02 ㎡ 지장물로
올라가 있었다). 그래서 **라벨이 자기 선에 밀착(0.6 m)했는지**, **설계사 종단과 맞는지**로
되돌린다(`11 --promote`).

```bat
set PY=python -X utf8

rem 1) 폴리곤 빌드 — 먼저 --write 없이 집계를 보고 나서 쓴다
rem    --out(기본 survey.build_gpkg)은 '기존 빌드 레이어가 들어 있는 GPKG' — 그 안의 --prev 레이어와

rem 2) ㄷ자 보정 → 반드시 04보다 먼저 (폭이 정상화돼야 04 판정이 맞는다)

%PY% %T%\03_fix_digeut.py --write
%PY% %T%\03_fix_digeut.py --review            rem 확인필요 레이어도 따로
```

## 합격 기준 (이게 "한 번에 올렸다"의 정의)

05가 세는 값이 모두 0이면 통과, 아니면 **그 목록만** 사람이 도면으로 확인한다.

| 항목 | 의미 | 목표 |
|---|---|---|
| 추정(기본폭) | 폭을 몰라 0.3 m로 버퍼한 것 | 0 |
| 미상·표기없음 | 규격 라벨을 못 찾은 것 | 0 (04-B로 채움) |
| 무효 폴리곤 | 자기교차 등 | 0 |
| 폭 비정상 | 0.05 m 미만 / 6.6 m 초과 | 0 |
| 중복 쌍 | 누적본 납품으로 이중 작도 | 0 |
| 04-A 폭 불일치 | 표기폭 ↔ 실측폭 20% 초과 | 0 |
| 06 규격상이·없음 | 종단과 안 맞음 | 상수관만 남아야 정상 |
| 13 사람확인·폭의심 | 되접힌 폴리곤 / 표기폭 ↔ 종단 크기 불일치 | 0 (구거 밖은 13으로 못 봄) |

**"오류 0"은 목표가 아니다.** 도면이 사람 보는 그림인 한 결정 불가능한 애매함이 남는다 —
실측 간격 1.0 m는 `U1.0 측구`일 수도 `D1000 관`일 수도 있고,
라벨 없는 단선 한 줄은 폭을 알 길이 없다. 그래서 목표는 **확인할 목록이 3~5건으로 줄어드는 것**이다.

**06 "없음"은 상수관만 남아야 정상**이다. 측량현황도는 지상 가시 구조물 대상이라 **지중 상수관을
담지 않는다** — 상수관 검토는 지장물 폴리곤이 아니라 상수관망 레이어(`layers.water_pipe`)로 한다.

## 사례 (한 실무 회차 — 도구가 뭘 잡아내는지)

측량 2회 누적 납품, 정본 지장물 약 1,500건 기준.

- `02` — 폴리곤 528 / 하수(기존) 302 / 맨홀 164 / 잔여선 20 · 237 m(원본 53,281 m 의 0.4%).

- `11` — 지장물 1504 → 1394, 확인필요 110. 약한 근거 353개 중 238개는 라벨 밀착·종단 검증으로 남고
  115개 분리, 그중 5개는 종단과 짝지어져 `--promote` 로 되돌아왔다(사각 토큰은 규격 비교를 생략하므로
  '위치일치'도 검증으로 본다 — 이 처리를 빼면 종단 지장물 3건이 짝을 잃는다).
- `05`(분리 후) — 단선버퍼 242 / 미상·표기없음 138 / 라벨 인접승계 38 / 폭 비정상 11 / 추정 1 / 중복 쌍 9.

## 반드시 지켜야 하는 기술 사항 (여기서 많이 깨졌다)

공통 함정은 킷의 `standard/pitfalls-dxf.md` · `standard/pitfalls-qgis-postgis.md` 에 있다
(DXF 인코딩, 대용량 DXF, PROJ 충돌, GPKG rtree 트리거, sqlite3 커서). 아래는 이 도구 코드에 직접 묶인 것.

- **DXF 인코딩** — AC1032는 `$DWGCODEPAGE`가 ANSI_949여도 실제 UTF-8이다.
  `ezdxf.read(open(path, encoding='utf-8'))` (`_common.load_dxf`).
- **100 MB 통짜 읽기 금지** — MemoryError. 01로 줄여서 쓴다. 필터는 code 0 청크 단위로 자르되
  `SECTION/ENDSEC/EOF`는 무조건 통과, `VERTEX/ATTRIB/SEQEND`는 부모 판정을 이어받아야 한다.
- **PROJ 충돌** — QGIS·PostGIS 를 깐 PC 는 `PROJ_DATA`가 그쪽으로 잡혀 pip fiona가 EPSG 조회에
  실패한다. `_common.py`가 import 전에 fiona 번들 `proj_data`로 덮어쓴다. **fiona보다 먼저
  `from _common import *`** 를 해야 한다.
- **GPKG 쓰기**
  - INSERT는 **fiona append**로만 된다(rtree 트리거가 `ST_MinX`를 호출 → 순수 sqlite3 불가).
    fiona는 스키마 전 필드를 요구하므로 없는 키는 None으로 채운다.
  - **속성 UPDATE도 sqlite3로는 막힌다** — `AFTER UPDATE ON`(컬럼 한정 없는) 트리거가
    WHEN 절에서 `ST_IsEmpty`를 평가한다. 그 트리거만 DROP → UPDATE → 원문 SQL 복원.
    **트리거 번호가 파일마다 다르다** → 이름이 아니라 **SQL에 'AFTER UPDATE ON' 포함 여부**로 찾는다.
    `_common.update_attrs()`.
  - **도형 교체는 DELETE + append**. `_common.replace_features()`.
- **sqlite3 커서 함정** — 같은 커서로 select를 돌면서 update하면 **첫 행만 반영된다**.
  먼저 `list()`로 받을 것.
- **굽은 띠의 폭** — 최소회전사각형 단변은 틀린다(L자 U1.0 측구가 17 m로 나온다).
  둘레·면적 역산 `P=2L+2w, A=Lw` 를 쓰고, **L/w ≥ 3** 인 띠에만 적용한다. `_common.band_dims()`.
- **ㄷ자 판정은 within으로** — 체인을 거리로 짝지으면 옆 폴리곤에 오배정된다.
  폴리곤 **안에 들어 있는** 체인만 그 폴리곤의 원본으로 본다.
- **`%%C` 정규식** — `'...%%C...' % NUM` 식으로 포맷하면 `%C`가 되어 `%%C600`을 못 잡는다.
  `%%%%C`로 쓰거나 포맷을 쓰지 말 것.
- **`U형측구06x06` 처럼 소수점 없는 2자리 `0N` 은 0.N m** (6 m 아님). 실측으로 검증됨.
- **GPKG 파일 잠금** — QGIS가 편집 중이면 충돌하니 작업 후 레이어 새로고침이 필요하다.
- **벽선 2줄이 끝점을 공유하면 linemerge가 한 줄로 붙인다** — 박스 토출부에서 양쪽 벽선이
  한 점에 모이면 그 절점은 차수 2라 `linemerge`가 **머리핀 한 줄**로 만들어 버린다.
  그 상태로 버퍼하면 되접힌 폴리곤이 된다. 꺾임각 ≥110° 인 정점에서 끊고 나서
  짝을 찾을 것. `13_gugeo_check.split_reversals()`.
- **되접힘을 '인덱스 비인접'으로 판정하지 말 것** — 정점이 조밀한 직선도 i 와 i+2 가 당연히
  가까워 전부 되접힘으로 걸린다. **선을 따라간 거리**가 `max(3w, 2m)` 넘게
  떨어졌는데도 직선거리가 가까운 경우만 되접힘이다. `13_gugeo_check.self_overlap()`.
- **지적도 지목 '구/천/유' 는 공짜 근거다** — 구거 복개 암거는 지적 필지가 선형·연장을
  잡아준다. 다만 **폭은 못 잡아준다** — 구거 필지 폭(8~10 m)이 구조물 폭(2~3 m)보다 훨씬 넓다.
  폭은 원도 마구리 실측·`.flo` 토큰 크기로 따로 간다.
- **중심선은 `band_axis` 로 만들지 말 것** — 굽은 띠에서 엉뚱한 현이 된다. 14·15 의
  `poly_centerline`(양 끝에서 경계를 갈라 호장 비례 평균)을 쓴다.

## 다음 회차에 "한 번에" 끝내려면

1. **입력을 바꾸는 게 가장 효과가 크다** — `측량성과_요청사항.md` 참조.
   지장물 블록에 ATTRIB(종류·규격·관저고)가 붙어 오면 추측이 0이 된다.
   설계사 평면도의 `속성맨홀`·`기타데이터` 블록이 그 방식이고, 1,177개를 읽어 수리계산 367구간과
   **불일치 0건**이 나온 적이 있다. 같은 방식을 측량 쪽에 요청하면 된다.
2. 입력이 안 바뀌면 **02 → 03 --write → 04 → 05 → 06** 를 매 회차 돌린다.
   03·04가 자동으로 잡는 비율이 약 15/19(79%)다. 남는 4건쯤은 원리상 측량도 안에 답이 없다
   (측량 미등록, 측량 vs 종단 상충, 종단만 아는 규격).
3. **측량도 하나로 지장물이 완성되는 일은 없다.** 지중 상수관은 지자체 상수관망 GIS,
   미등록 관은 설계사 종단·준공도에서 와야 한다.
