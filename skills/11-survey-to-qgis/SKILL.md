## 설정 — 하드코딩 없음

경로·레이어·필드는 프로젝트 루트의 `sewer.config.json` 에서 온다(킷 `lib/kitconfig.py`).
모든 스크립트가 `--config <경로>` 를 받고, 생략하면 `SEWER_CONFIG` → 현재 폴더에서 위로 탐색.
**명령줄 인자(`--gpkg` `--poly` `--cl` `--route` `--src` …)가 설정보다 우선**한다.

| 키 | 용도 |
|---|---|
| `layers.obstacle_poly` / `obstacle_line` | 지장물 정본 폴리곤·중심선 — **GPKG 만** |
| `layers.obstacle_review` / `obstacle_review_line` | 확인필요 폴리곤·중심선 |
| `layers.plan_pipe` (+ `fields.plan_pipe.pipe_id` `district`) | 설계 노선 — 종단 대조·금회 노선 거리 |
| `layers.parcel` (+ `fields.parcel.jibun`) | 지적 — 13 구거 기준자 |
| `fields.obstacle_poly.fix_note` | 보정 기록 필드(없으면 `보정_YYMMDD`) |
| `survey.dxf_dir` `design_check_gpkg` `build_gpkg` `current_districts` `flo` `parcel_encoding` | 측량 폴더·노선 GPKG·빌드 GPKG·금회 지구·종단 .flo·지적 인코딩 |
| `outputs.root` | 산출 루트 — 점검 결과는 `11-survey/` 아래에만 쓴다 |

설정이 없거나 키가 비면 스크립트가 무엇을 채우라고 안내한다. 처음이면 00-onboard 로 설정부터.
지장물 필드 이름(`지장물번호` `종류` `표기` `규격_폭m` …)은 **킷 표준 출력 스키마**라 설정으로 바꾸지 않는다.

## 왜 오류가 나는가 (한 줄 요약)

측량현황도는 **그림**이다. 지장물이 "폴리곤+속성"이 아니라 선 몇 개와 떨어진 텍스트로
표현돼 있어서, 변환이 아니라 **추측 3단계**(어떤 선이 한 지장물인가 / 폭이 얼마인가 /
어느 라벨이 누구 것인가)가 된다. 그래서 검사가 본체다.

## 실행 순서

공통 접두: `python -X utf8 "<SKILL>\tools\<스크립트>" --config "<프로젝트>\sewer.config.json"`
(`python -I` 는 fiona 를 못 불러올 수 있다 — `-X utf8` 로.)

| | 스크립트 | 하는 일 |
|---|---|---|
| 0 | `01_filter_dxf.py "<원본.dxf>"` | 100 MB → 경량 DXF (통짜 읽으면 MemoryError). 인자 없으면 `survey.dxf_dir` 목록 |
| 1 | `02_build_poly.py --prev <기존> --suf <새>` | 폴리곤·중심선·맨홀 빌드 (먼저 `--write` 없이 집계 확인) |
| 2 | `03_fix_digeut.py` (`--review` 도) | **ㄷ자 두께 2배 보정** ← 반드시 04 보다 먼저 |
| 3 | `04_check_labels.py` | 라벨 오귀속 점검 + 미상 규격 추정 |
| 4 | `05_qc_flags.py` | **품질 플래그 — 이 숫자가 합격 기준** |
| 5 | `06_check_profile.py` (`--review` 도) | 설계사 종단(.flo `x=`)과 교차 검증 |
| 6 | `11_split_unverified.py --promote` | 종단 검증분을 확인필요 → 지장물로 승격 |
| 7 | `07`→`08`→`09`→`10` | 문제건 정리 → 가짜 탐지 → 추적 → 삭제 |
| 8 | `12_merge_halves.py` | 반쪽 분할 폴리곤 병합 |
| 9 | `13_gugeo_check.py --fig` | 단선버퍼를 구거 필지로 검증(읽기만) |
| 10 | `14_reparse.py --from-13 사람확인` · `15_fix_centerline.py` | 원도 재파싱 · 중심선 정합 |

`run_all.bat [sewer.config.json] [원본.dxf]` = 01~06 보고 모드(설정 파일을 bat 위로 끌어다 놓아도 된다).

### 쓰기 규칙

- `--write` 는 **정본 GPKG 를 고친다.** 항상 먼저 `--write` 없이 돌려 목록·건수를 사용자에게 보여 주고,
  사용자가 승인한 것만 `--write` 한다. 백업(`_bak_YYMMDD_HHMM`)은 자동.
- 04 `--write` 는 B(미상 규격)만 반영 — 측구 폭이 표준관경과 겹치므로 `04_labels.csv` 를 먼저 훑는다.
- 10·12 의 삭제·흡수분은 `<산출>/11-survey/지장물_삭제이력.csv` 에 누적된다.
- QGIS 가 그 GPKG 를 편집 중이면 닫고 돌린다.

## 합격 기준

`05_qc_flags.py` 가 세는 값이 모두 **0** 이면 통과.

추정(기본폭) · 미상/표기없음 · 무효 폴리곤 · 폭 비정상 · 중복 쌍 · 04-A 폭 불일치 · 06 규격상이 · 13 사람확인
→ **06 "없음"은 상수관만 남아야 정상**(측량도는 지중 상수관을 안 담는다. 상수관 검토는 `layers.water_pipe` 로).

★ **"오류 0"은 목표가 아니다.** 도면이 사람 보는 그림인 한 결정 불가능한 애매함이 남는다.
목표는 **사람이 확인할 목록이 3~5건으로 줄어드는 것.**

## 근거의 세기로 레이어를 가른다

| 생성 경로 | 가는 곳 |
|---|---|
| 폐합(도면) · 체인쌍(평행 2선) | `지장물` |
| **단선버퍼 · 추정(기본폭)** | **`확인필요`** |

측량도는 경계선·구조물선도 `배수시설물` 레이어에 그려 넣는다 — 레이어만 봐서는 안 걸러진다.
라벨 밀착(0.6 m)·종단 일치로 되돌린다(`11 --promote`).

## 함정

킷 `standard/pitfalls-dxf.md` · `standard/pitfalls-qgis-postgis.md` 를 먼저 볼 것.
특히 **DXF 인코딩(ANSI_949 선언이나 UTF-8)**, **GPKG rtree 트리거**, **sqlite3 커서(첫 행만 반영)**,
**`%%C` 정규식**, **굽은 띠 폭은 둘레·면적 역산**, **ㄷ자 판정은 within 으로**, **벽선 끝점 공유 시 linemerge 머리핀**.
도구 코드에 묶인 나머지는 README 의 「반드시 지켜야 하는 기술 사항」 절.

다른 팀이 처음 쓸 때는 README 「일반화 한계」를 확인한다 — **DXF 레이어 이름(`배수시설물` 등)은
측량사 작도 규약**이라 다르면 코드의 레이어 목록을 고쳐야 한다.
